Backfill missing core info

      
Equivalent of scripts/backfill_core_ids.py (missing_core filter): queues a rescrape for every product with no core_id set yet (migration 007). Only enqueues -- the actual scrape happens asynchronously via each platform's own SQS-triggered scraper Lambda, so re-run this later (or just re-filter the Products tab) to see how much is left. Products on a platform with no scraper deployed yet (Hammer/Track/Ebonite) will keep showing up here -- that’s expected, not a bug.

      
      
      

      

    


    

      
Backfill missing coverstock info

      
Equivalent of scripts/backfill_coverstock_ids.py (missing_coverstock filter): queues a rescrape for every product with no coverstock_id set yet. Unlike cores, migration 008 already backfilled coverstock_id for every product that had coverstock_name at the time -- a product shows up here only if its own scrape never captured a coverstock (or the manufacturer's page has since changed and it hasn't been rescraped since). A rescrape also backfills material/type onto a shared coverstocks row for free if some earlier scrape created it without either (get_or_create_coverstock_id's coalesce). Only enqueues -- re-run later (or re-filter the Products tab) to see how much is left.
